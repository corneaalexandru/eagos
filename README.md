# EAGOS 4.0.0

**Evidence-led Agent Governance and Operations System**  
**From intent to governed action.**

## Purpose

Turn an unclear idea, problem, or objective into a practical project with classified knowledge, evidence-backed decisions, authorized activities, measurable outputs, and durable records.

**Build by Evidence, One Gate at a Time.**

Start with an idea, a practical problem, an objective, an existing project, or an operating organization. Use ordinary conversation. The agent helps clarify the outcome, contributes useful thinking, advances authorized work, validates results, and maintains continuity. Clarification, investigation, delivery and ongoing operation enter when relevant to the actual purpose. New venture ideation and opportunity selection belong to the portfolio owner. EAGOS supplies the method while the applicable portfolio owner keeps opportunity discovery and selection.

For organizations, the same principles govern agents that coordinate, decide, execute and review within defined roles and delegated authority. Each commitment remains tied to evidence, applicable gates and actual permission.

## Start here

> Help me turn this idea, problem, or objective into a practical result. Be an active thinking partner, distinguish what we know from what we assume, and recommend the next useful step. Carry out ready work within our agreed authority, validate the output, and keep the records current. Ask one important question when my input is needed.

Say “continue,” “review,” “change direction,” “pause,” or describe what you need. Users do not need to select an internal module or complete an intake to explore.

## A proportionate operating system

**Project → Workstream → Phase → Deliverable → Task.** A Task is the smallest useful executable unit with an owner, required inputs, valid authority, measurable output and completion check.

The conversational stages **Discover → Shape → Incubate → Develop → Launch → Operate → Evolve** describe useful focus. They are optional navigation, not new gates or authority. A project can finish without becoming a business. P0/P1/P2 select controls by consequence; personal/project/company context is a separate choice.

One hub can be enough for a small project. Add roles, records and software only when they improve execution, ownership, review or continuity. The agent organization is distinct from its technical deployment.

## Agent context: load only what the work needs

Start with the applicable `AGENTS.md`, the operating guide once, and the project's current hub/checkpoint. Follow pointers to the current Task, relevant evidence, dependencies and authority. On resumption, refresh changed state; do not reload unchanged guidance.

Use the table above to retrieve specialist guidance when needed. The full specification is a reference, not compulsory startup context. Never load both source and portable copies, recursively ingest the repository, or attach release history, archived specifications, tests or maintenance output to an ordinary project session. Retrieve history only to resolve a specific current question. Required evidence and authority must still be read.

## Package

EAGOS is a framework with portable records, optional offline tools and documented runtime profiles. OpenClaw and LangGraph profiles define candidate implementations; actual deployment needs configuration, tests and activation evidence.

Use [the project starter](10_eagos_project_starter/README.md) or [offline tools](20_tools/00_tools_index.md). The canonical specification is [00_eagos.md](00_eagos.md); the operating guide is distributed identically in the project starter. The [adoption guide](02_upgrade_guide.md) covers existing installations.

**Ownership update, 2026-09-24:** EAGOS no longer ships a separate opportunity starter or initializer. [Legacy record compatibility](02_upgrade_guide.md#compatibility-reference) remains read-only; use the applicable portfolio owner for new venture opportunities. Core version 4.0.0 is unchanged.
