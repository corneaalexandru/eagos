# Security

Do not report secrets, private prompts, customer data or exploit details in a public issue. Use GitHub private vulnerability reporting if enabled; otherwise request a private contact from the maintainer without disclosing the vulnerability.

Until a release has explicit support dates, security support is best effort. Pin reviewed dependencies and validate compatibility before upgrading. A passing test is not proof of a secure deployment.

Never place credentials in examples. Report the affected version, minimal synthetic reproduction, impact and proposed mitigation privately. Preserve audit history when investigating.
