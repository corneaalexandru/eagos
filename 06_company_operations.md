# ELAEF Company Operations

Apply the original project purpose to ongoing organizations: agents coordinate, decide, execute and review within defined responsibilities and delegated authority. Human ownership and reserved decisions remain explicit. This guide defines operational governance; it does not appoint legal officers or confer statutory authority.

## Three contexts, one core

| Context | Unit of responsibility | Useful starting structure |
|---|---|---|
| Personal or finite project | Outcome, deliverables and Tasks | One P0 hub when consequence permits |
| Multiple initiatives | Portfolio priorities and separate project truth | Portfolio pointers, capacity and dependency view |
| Operating organization | Continuing functions, processes and obligations | Organization charter, role/delegation map, recurring processes and performance review |

Context and conformance are different dimensions. P0/P1/P2 still describe consequence and required controls; a company label does not automatically select or downgrade a profile. Preserve applicable project policies. Discovery is available when useful and is not required before addressing an existing problem.

## Organization charter

Define purpose, beneficiaries/customers, value delivered, scope, constraints, success measures, available resources, reserved decisions, accountable humans, applicable obligations, and conditions for pause or closure. Classify uncertain commercial assumptions. Link to existing legal, financial and operational records instead of copying competing current versions.

The [organization guide](05_agent_organization.md) supplies the roles and authority model. Each material decision category states who proposes, decides, executes and reviews it. Examples include prioritization, procurement, pricing, publication, production changes and incident response. Default to existing authority; a template or role title never grants a commitment.

## Recurring process contract

A recurring process has an owner, trigger/cadence, intended result, inputs, authority, executor, reviewer, service/completion criteria, limits, escalation, recovery and record location. Use `60_templates/12_recurring_process.md` in the core starter when needed.

Create a separate Task/run identity for each occurrence while preserving its process ID. Carry forward cumulative budget and quota use across runs. Record missed or late occurrences and decide whether to skip, consolidate or catch up; do not replay an unbounded backlog automatically. Prevent overlapping runs where they could conflict or repeat external actions.

Schedules must be explicitly created and verified in the selected runtime. A cadence written in a document is not a running schedule. Standing authority can cover repeated actions only within its recorded limits and review conditions.

## Operating review

Maintain one derived owner view answering:

1. What outcomes and obligations are due, and what actual results exist?
2. Which Tasks are ready, running, blocked, overdue or complete with evidence?
3. Who or which agent owns each material responsibility?
4. Which decisions need the owner, and what concrete result is ready for review?
5. What resources have been allocated and used, and where are the exceptions?

Choose review cadence by operating need. Compare actual outcomes with defined objectives, inspect customer/beneficiary feedback, cost, rework, incidents and uncertainty. Separate activity counts from value delivered. A dashboard is derived from authoritative records and does not become a second source of truth.

## Incident, suspension and recovery

Assign severity, accountable owner, affected scope, containment and communication authority. Stop affected execution, preserve evidence, reconcile uncertain external outcomes, correct the cause, and test recovery. Continue independent work where authorized. Never retry an uncertain payment, message, deployment or other commitment without checking the actual state first.

Suspension must reach scheduled jobs, delegated sessions, connectors and credentials as appropriate. Record which controls were actually applied and any unresolved exposure. Resumption requires the applicable authority and current readiness evidence; a changed status label is insufficient.

## Improvement and closure

Propose process changes using observed results, a measurable hypothesis, a bounded trial, review criteria and rollback. Keep prior versions and decision evidence. Review role effectiveness and simplify unnecessary coordination.

When a project completes or an organization pauses/closes, record accepted outputs, remaining obligations, ownership of records and access, open incidents, resource release, retention and next review. Completion is allowed without business launch or continuous operation. Actual handover acceptance is separate from preparing the handover.

## Agent system and owner interface

Use the [AI agent system and owner dashboard](09_ai_agent_system_and_dashboard.md) for state-triggered preparation, approval/changes workflow, source freshness, revision-bound decisions and technical/owner separation. Implement and test the selected controls before claiming operational capability.
