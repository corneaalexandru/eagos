# Changelog

## 3.6.0 core / ODS 1.2.0 — 2026-09-16

- Added one conversational lifecycle across discovery, shaping, incubation, development, launch, operation, and evolution. Ordinary instructions work across stages.
- Made proactive contribution, opportunity recognition, grounded encouragement, and reasoned next-step recommendations explicit. Preserved owner direction, evidence, and actual authority.
- Added a shared portable operating guide, core hub checkpoints, lightweight initiative pointers, and an optional initiative template. P0 now installs the guide with its small baseline.
- Kept detailed ODS research/selection optional within the same experience, retained schema 1 and prior workspace compatibility, and linked continuation to authoritative receiving-project state.
- Added optional descriptive lifecycle-stage diagnostics, seven integration tests, and sixteen conversation-evaluation scenarios. Scenarios require actual response evidence before conversational effectiveness is claimed.
- Preserved core sections 1-96 and existing phases, gates, IDs, approvals, and record meanings. Specification sections 97-98 define the addition and release record.
- Published the generic core and optional ODS starter together. No automatic active-project migration, external launch, gate approval, or receiver acceptance is implied. See the [operating guide](04_operating_guide.md) and [upgrade guidance](02_upgrade_guide.md).

## 3.5.1 core / ODS 1.1.1 — 2026-09-14 (local maintenance)

- Shortened repeated core instructions and the quick start, package guide, agent contracts, and discovery playbook. Preserved all 96 core section numbers, record IDs, evidence meaning, gate controls, and approvals.
- Replaced duplicate hub definition fields with links to charter/state authority. Setup records now require actual owner scope and confirmed readiness rather than deriving permission or readiness from a template.
- Corrected stale version references, the embedded master hub's active default, naming/numbering guidance, and the block-reference example.
- Fixed false activation conflicts between `not_assessed` and `not-assessed`; diagnostics remain read-only and neither spelling passes activation.
- Kept discovery schema 1 and compatibility with ODS 1.0.0/1.1.0; new generic files declare 1.1.1. Existing project records and manifests remain unchanged.
- Added compatibility regression coverage and current-specification verification; tests no longer silently inspect the older public checkout. Preserved backups, prior handover, and lifecycle history.
- This was a local maintenance revision before the 3.6.0 release. It implied no active-project migration, gate approval, or receiver acceptance. See the [upgrade guidance](02_upgrade_guide.md).

## ODS 1.1.0 extension — 2026-09-12 (local implementation)

- Changed the default entry point to interactive discovery with an AI agent: explore, shape, research, challenge, compare and prepare as flexible conversational moves.
- Added a reusable playbook, one-question dialogue loop, diverse idea-generation lenses, lightweight idea board, conversation checkpoint and resumption guidance. Research scans remain explicitly available as an optional mode.
- Made evidence collection and detailed screening progressive; incomplete early ideas do not require a fabricated research cycle, numeric ranking, budget or business model.
- Preserved the earlier personal research cycle and installation manifest. Recorded the owner's interaction correction, superseded the old proposed allocation, and retained previous evidence and IDs.
- Kept schema 1 and ELAEF core 3.5.0; the optional checker accepts ODS 1.0.0 and 1.1.0. Added compatibility and new-portfolio coverage. Conversation quality is not structurally validated.
- Local revision only; existing execution projects and the public release are unchanged.

## ODS 1.0.0 extension — 2026-09-12 (local implementation)

- Added Opportunity Discovery and Selection before project-level ELAEF execution, compatible with core 3.5.0 under its extension contract. Core version and existing execution starters are unchanged.
- Added a portable discovery starter with a single authoritative workspace, classified mandate, bounded research loop, claim-level evidence/counterevidence, three comparison profiles, hard filters, sensitivity checks, next-test proposals, and selection/receipt controls.
- Added optional standard-library `01_discovery.py` initialization and structural checks, with disposable regression scenarios for evidence, unknown ratings, constraints, limits, and handover integrity.
- Prepared a separate private working portfolio with unknown owner constraints retained. No live opportunity research, selection, promotion, or public release is implied by installation.
- Added navigation, adoption guidance, validation evidence, and continuation records. The previous 3.5 handover is preserved; personal portfolio records are excluded from public packaging.
